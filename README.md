# AI Study Tool

## 1. アプリ概要・スクショ・デモ

**Kindle等で学んだ知識をアウトプットし、他者の考え方から理解を深める学習アプリ。**

AI Study Toolは、Kindleのハイライトやユーザーが取り込んだテキストからAIが問題を生成し、解答・復習や解説の共有ができる学習アプリです。

読書で得た知識を問題を通じて確かめ、不足している知識を学び直すことで、インプットとアウトプットを繰り返しながら理解を深めます。

また、大学の過去問対策で毎年似た問題に対して同じような解説が作られていることに着想を得て、学習者の解説や思考過程、周辺知識を1つの本に対して読者全員で蓄積・共有する仕組みを考えました。

問題を解くだけでなく、他の学習者の解説を通じて、自分にはなかった視点や知識同士のつながり、体系的な知識の理解も学べる環境を目指しています。

### 学習の流れ

1. **取り込む**：Kindleのハイライトや任意のテキストを取り込む
2. **問題を解く**：AIが生成した問題に解答し、理解度を確認する
3. **復習する**：解説を読み、保存した問題や間違えた問題を解き直す
4. **共有する**：自分の解説や考察を投稿し、他の学習者の知識や考え方を学ぶ


### 操作デモ


テキスト取り込み → 問題への解答 → 解説の確認 → 投稿・共有までの一連の操作を紹介する動画を掲載予定です。公開デモ環境も今後追加予定です。

## 2. 開発背景と解決したい課題

### 解決したい課題

世の中には学びのある書籍が数多くありますが、本を読む学習は知識のインプットが中心になりがちです。

本を読んで知識を得ても、実際の試験や仕事でどのような場面に、どの知識を使えばよいのか判断できず、学んだことを十分に活かせないという課題を抱えている人が多いのではないかと考えました。

### 解決方法

そこで、次の2つを組み合わせた学習環境を作りたいと考えました。

1. **知識のアウトプット**
   学んだ知識を問題としてアウトプットする機会を設け、理解が不足している部分を明らかにする。
2. **知識体系のインプット**
   知識同士の関係や問題解決のパターンを体系的に理解し、試験や仕事で活用できる形で学ぶ。

### 開発のきっかけ

大学の過去問対策で、毎年似たような問題に対して似たような解説が作られていることから、学習者の解説や思考過程を本単位で蓄積・共有する仕組みに着想を得ました。

自分で問題を解くだけでなく、他の学習者がどのように問題を捉え、知識を関連づけているのかを学び、自分にはなかった視点や周辺知識も得ることで、アウトプットと知識体系のインプットを組み合わせた学習を目指しています。

### 主な機能の使い方

#### 1. Kindleハイライト・テキスト取り込み

Kindle NotebookのハイライトをChrome拡張機能から取り込めます。また、テキストの直接入力やモバイルの共有機能にも対応しています。


#### 2. AIによる問題生成・解答

取り込んだテキストからAIが問題を生成します。

- 本ごとに問題を管理
- 問題に解答して正誤を確認
- 解答後に解説を表示

> 📷 

#### 3. 保存した問題・間違えた問題の復習

解答した問題を保存したり、間違えた問題を一覧から解き直したりできます。

> 📷 

#### 4. 解説・考察の投稿と共有

解いた問題に自分の解説や考察を添えて投稿できます。

また、他の学習者が投稿した問題・解説を閲覧し、いいねやコメント、フォローなどを通じて交流できます。

> 📷

### 今後の構想：体系的な知識を学べるAI解説

現在のAIによる問題解説を拡張し、正解の理由だけでなく、以下の情報も提供できるようにしたいと考えています。

- **上位概念**：その知識が体系全体のどこに位置するか
- **関連知識**：他の知識とのつながりや周辺知識
- **応用パターン**：他の問題や実際の場面でどう活用できるか

これにより、問題を解くことが新たな知識のインプットにつながり、個別の知識を体系的に理解できる学習体験を目指します。

#### 実装に向けた課題

- **AIの生成精度**：AIは個別の事実を説明できても、抽象的な上位概念や知識同士の関係を適切に整理することが難しい場合がある。
- **ユーザー体験**：体系的な解説は情報量が多くなりやすく、すべての学習者にとって理解しやすいとは限らない。

そのため、解説の正確性や理解のしやすさを検証し、学習者が必要に応じて詳細な解説を参照できるような提示方法も検討したいと考えています。

## 5. 特に工夫した点

### 5.1 部分ユニークインデックスによるジョブの重複防止

**課題**：問題生成リクエストの連打や同時実行によって、同じユーザー・書籍に対する生成ジョブが重複する可能性がある。

**設計**：PostgreSQLの部分ユニークインデックスを使用し、`queued`・`processing`・`enqueue_failed`状態のジョブだけに一意制約を適用。

**理由**：アプリケーション側の事前チェックだけでは同時実行時の競合を防げない。DBで重複を保証しつつ、完了・失敗したジョブは履歴として保持できる。

**検証**：実DBを使った統合テストで、同じユーザー・書籍の有効なジョブを重複登録できないことを確認するテストを実装。

### 5.2 トランザクションによる問題生成結果の整合性保証

**課題**：問題の保存とジョブの完了状態を別々に更新すると、途中で失敗した際に「ジョブは完了したのに問題が保存されていない」などの不整合が発生する。

**設計**：問題の保存・旧問題の更新・ハイライト状態の更新・ジョブの完了を1つのDBトランザクションで処理する。

**理由**：個別に更新する方式と異なり、すべて成功した場合だけコミットすることで、部分的な更新を防げる。一方、トランザクション内の処理が増えるため、保持時間には注意が必要。

**検証**：ジョブの状態遷移を統合テストで確認し、問題生成処理の成功・失敗時の分岐を単体テストで検証。

### 5.3 APIスコープによる最小権限の認可設計

**課題**：Chrome拡張機能に通常の認証情報を共有すると、ハイライト取り込みに不要な投稿・課金機能まで操作できてしまう。

**設計**：拡張機能専用トークンを発行し、権限をハイライト関連の操作と自身のトークン失効に限定。APIごとにスコープを検証し、権限外の操作はHTTP 403で拒否する。

**理由**：全権限を共有する方式よりも、トークン漏洩時の被害を限定できる。ただし、APIごとの権限管理が必要になる。

**検証**：許可された操作は成功し、問題生成・課金操作は403で拒否されることをテスト。

## 8. 起動手順・今後の課題

### 起動手順

#### 必要な環境

- Go 1.26.5
- Node.js 22
- Docker / Docker Compose
- PostgreSQLクライアント（psql）
- Firebase Authenticationの開発用設定

#### 環境変数の設定

```bash
cp backend/.env.example backend/.env
cp frontend/.env.example frontend/.env
```

各`.env`に必要な接続情報を設定してください。

主な設定項目：

- `DATABASE_URL`：PostgreSQLの接続先
- `FIREBASE_CREDENTIALS_PATH`：Firebase Admin SDKの認証情報
- `CSRF_SECRET`：CSRFトークンの署名用シークレット
- `VITE_FIREBASE_*`：WebクライアントのFirebase設定
- `GEMINI_API_KEY`：Gemini APIの認証情報

#### データベースの起動

```bash
docker compose up -d postgres
make migrate
```

> [!NOTE]
> `make migrate`はSQLエラーを出力上で無視する場合があるため、実行後に必要なテーブル・インデックスが作成されたことを確認してください。

#### バックエンドの起動

```bash
make backend
```

API：http://localhost:8080

#### フロントエンドの起動

別ターミナルで以下を実行します。

```bash
cd frontend
npm ci
npm run dev
```

Web：http://localhost:3000

#### 起動後の動作確認

1. Webアプリにログインする
2. Chrome拡張機能をWebアカウントと連携する
3. Kindleのハイライトを取り込む
4. AIで問題を生成する
5. 問題に回答し、復習する
6. 解説や思考過程を投稿・共有する

#### ローカル実行時の注意点

- Firebase Authenticationの設定がなければ、ログイン機能は利用できません。
- `USE_GEMINI_MOCK=true`で、外部LLMを呼ばないダミー問題生成に切り替えられます。
- ただし、現在の非同期ジョブ構成では、Cloud Tasksなどのジョブ実行環境を設定しないと、問題生成の一連の処理は完了しません。
- Chrome拡張機能やMobileアプリの実行には、それぞれ追加のビルド・接続設定が必要です。
- APIキーや認証情報などの秘密情報はGitにコミットしないでください。

ローカルでのAPI・Web起動と、外部サービスを含む主要機能の動作確認は区別しています。
