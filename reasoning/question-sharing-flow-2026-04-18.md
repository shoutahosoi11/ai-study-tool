# Question Sharing Flow 設計メモ

## 現在のフロー

問題共有は「問題を解く」体験の後段として扱う。

1. 1問ずつ全画面で解く
2. 最後に解答まとめ画面へ進む
3. 各問題ごとに答え・解説・メモを確認し、必要ならその問題だけ保存する
4. `ポスト画面へ進む`
5. 一言メモを書いて `ポスト`
6. 成功後はタイムラインへ戻る

## なぜこの形にしたか

### 問題ごとの保存を先に置く理由

共有したいかどうかと、手元に保存して復習したいかどうかは別だから。解答まとめで各問題を個別保存できるようにして、共有の有無に引っ張られないようにしている。

### 一言メモを別ステップにした理由

問題ごとのメモと、投稿本文は役割が違う。

- 問題ごとのメモ: 自分の復習用
- 投稿本文: タイムライン上で問題セットの上に出す一言

同じ入力欄にすると意味が混ざるので、review と share を分けている。

### タイムラインへ戻す理由

ポスト完了後にその結果をすぐ確認できる方が自然だから。ブラウザ版は `onShareSuccess` でタイムラインへ遷移し、モバイル版も同じ体験に寄せている。

## 現在の UI ルール

- 解答中は全画面モーダル
- 進行は `→` ボタン
- 解答まとめでは各問題に AutoGrow なメモ欄
- 共有ステップでは一言メモ欄と `ポスト` ボタン
- 投稿詳細やタイムライン上の問題セットから解いた場合も、同じ共有導線に乗せる

## 実装上の責務

### `QuestionQuizSessionModal`

- 1問ずつの解答 UI
- 解答結果の保持
- 問題ごとの保存
- ポスト画面への遷移

### `KindleBookSection`

- Kindle 本起点での問題取得
- 共有成功後のタイムライン遷移

### タイムライン側

- 投稿された問題セットの取得
- 投稿詳細表示
- 投稿から解いた後の再共有導線

## 古い前提として捨てたもの

- 「問題を作る」ボタン中心の呼び方
- generate / solve の違いを見た目で大きく分ける設計
- 「投稿して閉じる」で終わる単発フロー

現在は「学習して、必要なら保存して、そのあとポストする」流れに寄せている。
